Trainer / facilitator control notes

Facilitation posture: demonstrate only enough to unblock the next decision. Do not take over the keyboard. Ask for evidence at every checkpoint.

  • Check that the graduate can explain why the chosen tool/pattern fits the problem.
  • Reject outputs that hide unresolved exceptions or unverifiable numbers.
  • Require a working artifact or evidence before marking the day complete.
  • For public GitHub work, use synthetic/sanitised data only.

⚙ Exercise / Activity

Decision Surface v1

The sponsor should be able to understand what requires attention without reading the code or raw dataset.

  1. Choose only KPIs that support the sponsor decision.
  2. Create a priority/risk queue rather than charts alone.
  3. Show data-quality or process exceptions visibly.
  4. Add owner / next action / due date where relevant.
  5. Write 3 management findings using “what happened / why it matters / action”.
  6. Test the page with another graduate for 60 seconds of silent use.
Required deliverables
Management interface v1
Priority queue
Three findings/actions
60-second usability feedback
