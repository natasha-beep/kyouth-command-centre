DIVISION PROJECT · TRACK D

Utilities & Facilities Exception Monitor

Utility and facility usage records require repeated comparison to find abnormal cost/usage movements. Build an exception monitor that identifies material changes, records investigation ownership and produces a monthly action queue.

Prepared project mission

Utility and facility usage records require repeated comparison to find abnormal cost/usage movements. Build an exception monitor that identifies material changes, records investigation ownership and produces a monthly action queue.

Required build

  • Trusted input transformation and exception handling.
  • At least one automated repeatable step.
  • Management-facing interface/report with next action.
  • Failure/exception evidence and runbook.
  • Sponsor validation against explicit acceptance criteria.

Discovery questions

  1. Which decision is delayed today?
  2. Which step is repeated manually?
  3. What input is trusted, and by whom?
  4. What exception must never be hidden?
  5. What would make the sponsor accept the solution?

Final proof

Working solution + source/logic evidence + one automated step + management-facing output + README/runbook + sponsor validation + 5-minute pitch.
